# docs/product-specs/

Product specifications are the **canonical source of truth** for what this project is supposed to do. Other documents derive from these.

## What lives here

- `initial-seed.yaml` — the original, canonical spec produced by `/harness-spec`. Drives every rendered document: AGENTS.md, ARCHITECTURE.md, core-beliefs.md, development-rules.md, and the consistency manifest.

## Editing rules

- This is the only document you should edit when changing project scope. Then run `/harness-spec --rerender` to propagate.
- Hand-edits to rendered documents will be overwritten on the next rerender; the rerender guard catches structural divergence.
- `initial-seed.yaml` itself is hand-edited; it is not regenerated by anything. Treat it like source code.

## When to add a file

- A new product spec for a major sub-feature whose scope outgrows a single AC in `initial-seed.yaml`. Cross-link it from `initial-seed.yaml` if you do.
